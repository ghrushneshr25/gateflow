# CHANGE-20261020 — P4.4.1 PostgreSQL admission coordination fence

## Decision

- Durable single-row `coordination_state` for admission grants.
- Modes: `ACTIVE` | `FENCED`.
- Epoch increments on each successful fence (audit trail).
- `GrantFIFO` takes `FOR UPDATE` on coordination row **before** budget/entitlement work and holds until commit.
- Fence API takes same lock, sets `FENCED`, commits, then returns success → no later grant can commit under prior ACTIVE.
- Unfence is explicit JWT-authorized only; never automatic on startup.
- Redis out of scope.

## Auth scopes

- `ops:admission:read` — GET coordination
- `ops:admission:fence` — fence / unfence

## Error

- `ADM_COORDINATION_FENCED` when grants blocked.
