# CHANGE-20261020 — P4.3 Kafka outbox publisher and consumer dedupe

## Decision

- Confirm still commits order + outbox atomically; **never waits on Kafka**.
- Publisher claims unpublished rows with `FOR UPDATE SKIP LOCKED` + lease (`locked_until`/`locked_by`).
- Produce to topic `gateflow.order.order.confirmed` with key=`aggregate_id` (order id).
- Set `published_at` only after Kafka ack.
- Crash after publish before mark → republish same `event_id`; consumer dedupes via `processed_events`.
- Consumer is order-owned auditor that records first-seen `event_id`.

## Alternatives

- Sync publish in Confirm — rejected (blocks business path on Kafka outage)
- Transactional Kafka + DB — out of scope / not available across systems

See `docs/execution/PHASE4.3.md`. Kafka integration tags `integration,kafka` PASS against Compose Kafka 3.8.1.
