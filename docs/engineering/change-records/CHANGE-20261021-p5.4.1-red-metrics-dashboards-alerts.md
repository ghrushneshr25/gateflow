# CHANGE-20261021 — P5.4.1 RED Metrics, Dashboards, and Alerts

## Summary

Added low-cardinality Prometheus RED metrics on all five Go services, booking/ops gauges (outbox, recon, admission fence, payment/compensation), Prometheus scrape + alert rules, Grafana Ops dashboard provisioning, and live fire/resolve evidence for required alerts.

## Problem and motivation

P5.4.0 delivered tracing. Operators still lacked request rate/error/latency series, backlog gauges, dashboards, and actionable alerts tied to runbooks.

## Requirements addressed

- RED metrics for sale, admission, inventory, order, payment-simulator
- Outbox / recon / admission / payment ops metrics
- Prometheus scrapes real `/metrics` endpoints
- Grafana dashboard from version control
- ≥3 alerts with thresholds + runbook links + fire/resolve proof
- Cardinality safety; no commit/push

## Previous → new behavior

| Before | After |
|---|---|
| Only OTLP collector scrape on :8889 | Apps expose `/metrics`; job `gateflow-services` scrapes :8081–8085 |
| No application RED series | `gateflow_http_requests_total` + duration histogram |
| Admin JSON outbox metrics only | Prometheus gauges + publish counters |
| No dashboards | `gateflow-ops` provisioned |
| No alert rules | 5 rules including 3 required |

## Decision tree

1. **OTLP metrics vs direct Prometheus?** Chose direct `client_golang` `/metrics` for reliable scrape, known ports, and simple PromQL without depending on collector metric conversion.
2. **Scrape path?** Host processes + `host.docker.internal` (local dev topology). Avoided dual-scrape of same RED via collector.
3. **Gauge cadence?** 15s ticker from PG — balances freshness vs DB load.
4. **Alert thresholds?** 120s outbox age / any quarantine / recon>5 for 5m — actionable without flapping on brief blips.

### Rejected

- Only OTLP→prom exporter for app RED (harder route templates, collector dependency)
- High-frequency gauge poll (<5s)
- Unbounded labels (path, error string)

## API / event / DB impact

None on public APIs or events. `/metrics` is a new unauthenticated local scrape endpoint (network isolation assumed).

## Invariants preserved

Payment≠confirm; PG authority; expired seats never revive; stable IDs; Redis not grant authority.

## Failure modes

- Collector down: unrelated; metrics still local.
- Prometheus down: booking continues; alerts silent.
- Target down: `GateflowServiceTargetDown` fires (missing scrape ≠ healthy zero backlog).
- Shared registry zeros on non-owner services: filter `service=` label.

## Tests

- VS1 live metrics movement
- Live alert fire/resolve for outbox age + quarantine
