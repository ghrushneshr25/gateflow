# CHANGE-20261020-p4.5-crash-recovery

## Summary

Add process-kill crash barriers and an integration harness that starts real service binaries, kills the order process at payment/compensation/outbox/consumer windows, restarts against the same durable dependencies, and asserts recovery invariants.

**P4.5.1:** Closed Scenario B (compensation crash after INV_EXPIRED) end-to-end with real SIGKILL + durable asserts.

## Problem and motivation

P4.1–P4.4 proved recovery logic in-process. P4.5 requires evidence that **actual process death** at ambiguous windows still yields correct durable state (no double charge, no lost confirm, no duplicate effects).

## Requirements addressed

- Real process/container death + restart vs same Postgres/Kafka
- Payment lost-response resume with stable operation id
- Outbox ack-before-mark reclaim
- Consumer DB-before-offset redelivery dedupe
- Local-only; no Redis on grant path

## Previous vs new behavior

| Area | Before | After |
|---|---|---|
| Crash injection | None | `testhooks.MaybeCrash` / `MaybeCrashOn` behind `GATEFLOW_TEST_HOOKS` |
| Publisher | Mark published immediately after Kafka ack | Optional crash window between ack and mark |
| Consumer | Commit after apply | Optional crash window after apply before commit |
| Tests | Unit/integration without process kill | `services/order/tests/crash` + `make test-crash-recovery` |
| Runtime | Always pub+cons when Kafka up | Optional disable via `GATEFLOW_OUTBOX_*`; test lease 2s; group override |
| Compensation S2S | Required JWT often missing on Advance | Order auto-mints/uses service token for EnsureCompensation |
| Order lease | Hardcoded 300s | `ORDER_LEASE_SECONDS` env override |

## Decision tree

1. In-process fault injection only? Rejected — does not prove process death.
2. Chaos mesh / k8s kill? Deferred — local binary kill is enough for P4.5 gate.
3. Shared consumer group for all crash tests? Rejected — lag/flakes; use filters + isolated groups.
4. Public admin “crash now” API? Rejected — test env only.

## Chosen approach

Env-gated hooks + OS process start/SIGKILL/restart harness; barriers write files under `GATEFLOW_HOOK_DIR`; scenarios assert Postgres durable state after restart.

## API / event / DB impact

None for production contracts. Test-only env vars. No migrations.

## Invariants preserved

- Inventory and purchase-limit invariants unchanged
- Payment success ≠ confirm
- Stable payment and outbox event ids
- Effect dedupe on redelivery
- Redis not authority for grants

## Failure modes and recovery

| Window | Recovery |
|---|---|
| After payment success, before order status write | Resume/reconcile via same idempotency key + payment lookup by operation id |
| After compensation create, before order RECON/comp-id write | Resume Advance; EnsureCompensation idempotent on `comp_<payOp>`; never confirm released/expired seat |
| After Kafka ack, before published_at | Lease expiry/reclaim; republish same event_id; consumer dedupe |
| After effect row, before offset commit | Redelivery; `processed_events` / effects unique on event_id |

### Scenario B operation-ID assertions

- `payment_operation_id` unchanged across kill/restart
- Compensation op = `comp_<payment_operation_id>` created once at payment DB
- Order records same `compensation_operation_id` after recovery
- Second reconcile does not create a second compensation
- Order never `CONFIRMED`; reservation not revived to ACTIVE/CONFIRMED

## Security / ops

- Hooks inert unless `GATEFLOW_TEST_HOOKS=1`
- Service token is local-dev JWT (same secret as existing authn); no production kill switches
- No secrets committed

## Known limitations

- **Scenario B / natural expiry distinction:** B proves compensation crash recovery after inventory is non-confirmable (deterministic **release** while Order is down). It does **not** by itself prove natural lease-timer expiry (60s min clamp, expire-due scheduling, wall-clock multi-service path). Inventory expiry races remain covered by inventory integration tests; a dedicated natural-expiry timing e2e is optional follow-up.
- Short outbox lease under test hooks only (`GATEFLOW_TEST_HOOKS=1` → 2s reclaim)
- Full Docker-level Kafka cold-start recovery not automated (Runtime reconnect unit/integration approximates)
- Not committed/pushed
