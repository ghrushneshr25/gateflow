# CHANGE-20261020 — P4.2 Payment ambiguity, late success, compensation

## Security finding (preflight)

**Confirmed defect (P4.1):** `POST /v1/orders/{id}/reconcile` and `GET /v1/admin/reconciliation` treated caller-controlled `X-Ops-Role` / `X-Service-Name` as credentials.

**Fix:** Require `Authorization: Bearer <dev JWT>` with `principal_type` in `{operator,service}` and required scopes. Buyer routes use buyer JWT or existing `X-Buyer-ID` only for buyer identity after optional bearer; privileged routes never trust bare role headers.

## Objectives

1. Payment scenarios: delay_success, unknown, duplicate callback, compensation_fail  
2. 3-minute payment deadline without extending reservation lease  
3. Late pay after expiry → no revive, no confirm, durable compensation once  
4. Authorized compensation retry; unauthorized rejected  

## State notes

- Payment: PENDING → SUCCEEDED|FAILED|UNKNOWN  
- Compensation: CREATED/PENDING → SUCCEEDED|FAILED|UNKNOWN; operation_id stable per payment  
- Order: RECONCILIATION_REQUIRED holds compensation_operation_id reference (optional field)
