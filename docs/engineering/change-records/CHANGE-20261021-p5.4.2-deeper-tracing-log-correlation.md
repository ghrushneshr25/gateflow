# CHANGE-20261021 — P5.4.2 Deeper Tracing and Log Correlation

## Summary

Propagate W3C Trace Context through Kafka outbox publish/consume with documented async span-link semantics, persist optional trace carriers on outbox rows, enrich structured logs with correlation/trace IDs, and ship host app logs to Loki via Promtail.

## Problem

HTTP traces stopped at request boundaries. Async outbox publish/consume had no Tempo linkage. Loki DS existed but no log ingestion. Operators could not follow a booking into Kafka processing via traces or log search.

## Approach

1. Durable `outbox.trace_carrier` at Confirm (from active span).
2. `kafkax.PublishWithTrace` / `ProcessContext` for inject/extract + spans.
3. Consumer: new root + span link (async policy).
4. `GATEFLOW_LOG_DIR` + Promtail → Loki.
5. Tests with in-memory OTel exporters.

## Alternatives rejected

- Stuffing trace IDs into event payload (contract pollution).
- Making consumer a child of checkout (misrepresents async).
- Docker-only log collection (host-run binaries are primary local topology).

## Schema

- Migration `000008_p5_4_2_trace_carrier`: nullable `TEXT` column; backward compatible.

## Invariants

- Event ID / payload / dedupe / commit-after-DB unchanged.
- Payment success ≠ confirm.
- Telemetry failure never blocks booking.
